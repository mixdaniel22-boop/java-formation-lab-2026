Performance ORM: el problema N+1

Cargas N órdenes con 1 query y luego Hibernate lanza N queries más para sus ítems y N×3 para sus productos. Con 100 órdenes: 1 + 100 + 300 = 401 queries.

Pruébalo

mvn spring-boot:run -Dspring-boot.run.profiles=dev
GET /api/orders
GET /api/orders/paged?page=0&size=20

Cómo detectarlo

  • spring.jpa.show-sql=true y contar sentencias repetidas.
  • hibernate.generate_statistics=true y Statistics.getPrepareStatementCount() (ver QueryCounter en los tests).

Cómo corregirlo

  • JOIN FETCH en JPQL (cuidado con paginación y colecciones: HHH90003004).
  • @EntityGraph como alternativa declarativa.
  • hibernate.default_batch_fetch_size para paginados.
  • No uses FetchType.EAGER: mueve el problema, no lo resuelve.
